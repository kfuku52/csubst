# PEPC joint endpoint: 連続サイト処理と枝メッセージの再利用

前回のイベント直接集計版を同じ環境で再測定したところ、枝別表ありのarity 6 searchがさらに約23%短縮した。全32試行・176表で、丸め前の数値・枝ID・置換文字列が完全一致した。

## 処理時間

秒、各条件ウォームアップ1回＋測定3回。表は中央値（最小–最大）。BLASスレッド数は1。

| 枝別表 | CPU | 前回実装（今回再測定） | 今回実装 | 中央値の短縮 |
|---|---:|---:|---:|---:|
| あり | 1 | 12.74 (12.51–12.86) | 9.80 (9.77–10.60) | 23.0% |
| あり | 4 | 12.56 (12.45–13.09) | 9.73 (9.66–10.46) | 22.6% |
| なし | 1 | 8.65 (8.53–8.82) | 8.31 (8.20–8.43) | 3.9% |
| なし | 4 | 8.73 (8.66–10.03) | 8.72 (8.28–10.15) | 0.2% |

枝別表なしはCPU 1で小幅な短縮、CPU 4では差がばらつきに埋もれたため、条件全般での高速化は主張しない。

計測範囲は入力読み込み、推論、arity 2–6、TSV出力、検証用pickle保存。Python起動と共通モジュールの事前読み込みは除外。起動を含む実時間、CPU時間、RSS、全コマンド、ソース・拡張・入力のSHA256は [matrix.json](matrix.json) に記録した。

共有マシンで前後を交互に測定。別のpytestプロセスは検出されず、ホスト全体の稼働は約4.1–5.3 CPU相当だった。前回測定時（約8.9–11.5 CPU相当）とは負荷が異なるため、前回レポートの13.7秒を今回の比較基準にしていない。枝別表ありはCPU 1・4とも前後の測定範囲が重ならなかった。

## 実装

1. Cythonのイベント集計を、コドン組合せごとに連続したサイト軸を処理するループへ変更した。組合せインデックスと遷移確率をループの外で読み、コンパイラが連続サイトの演算をベクトル化できるようにした。サイトごとの加算順序は維持している。
2. 系統樹の後向き計算で求めた枝メッセージを、前向き計算でそのまま分母として使用する。前向き事後確率用の既存バッファに一時保持し、使用後に事後確率で上書きするため、木全体の追加バッファは不要。

イベントカーネルはブロック内で転置した連続配列を作るため、ブロック内コピーと一時領域は増える。サイト数全体に比例する追加キャッシュは導入していない。枝別表ありの親プロセスRSS中央値はCPU 1で764→764 MiB、CPU 4で764→746 MiBだった。メモリ削減を目的とした変更ではない。

プロファイル上のイベント変換時間は前回版約3.98秒→ループ変更後約1.32秒。これはプロファイル実行の診断値で、上表は別途行った非プロファイル測定。

## 出力・テスト

全32試行でarity 2–6のCB表を検証し、枝別表ありの16試行では枝別表も検証した。合計176表がDataFrameの完全一致比較を通過。閾値判定、枝ID、NaN/±Inf位置も同じ。数値許容誤差と比の分子・分母の誤差伝播を用いる既存比較も通過した。[validation.json](validation.json) と [verify.py](verify.py) に詳細を保存。

候補行数はarity 2–6で8446 / 416 / 87 / 14 / 1、閾値通過数は85 / 45 / 20 / 6 / 1。arity 6の枝IDは全試行で `[1, 26, 33, 35, 40, 102]`。

全体テスト2114 passed、5 skipped。ネイティブ専用は16 passed（全体テストと重複）。lint・文書検査・型検査も成功した。新カーネルは連続・非連続配列とサイト数1 / 7 / 64 / 129で検証。枝メッセージ再利用は、全状態列挙を正解とする混合速度・ゼロ速度・欠損・ブロックサイズの既存テストで検証。[checks.log](checks.log) を参照。

## 再現

環境: Apple M2 Max、64 GiB、12論理CPU。Python 3.10.14 / NumPy 1.26.4 / SciPy 1.15.2、macOS上のx86_64実行。

比較対象はコミット `72c3c45` に前回の未コミット高速化を適用した状態。[baseline.patch](baseline.patch) はその3つの実装ファイルを復元する差分で、適用後のソースが凍結ベースラインと一致することを検証済み。`72c3c45` のソースを展開したディレクトリ内でこの差分を適用し、互換性のある環境で拡張をビルドする。今回版の拡張も同じ環境でビルドする。

```bash
python .github/scripts/benchmark_endpoint_scaling.py \
  --baseline-root /tmp/csubst-events-round2-before --baseline-mode joint \
  --scenarios heuristic6_b heuristic6 --cpus 1 4 --blas 1 --repeats 3 \
  --workdir /tmp/csubst-endpoint-events-round2-matrix \
  --result reports/endpoint_event_vectorization_20260910/matrix.json
python reports/endpoint_event_vectorization_20260910/verify.py \
  --workdir /tmp/csubst-endpoint-events-round2-matrix
```

ワーカーの生データとログは上記workdirに保存。cutoffは `OCNany2spe,2.0|omegaCany2spe,5.0`。同梱の既存IQ-TREE入力を使用し再推定しない。
