# Higher-order branch search

`csubst search --max_arity K` examines independent branch combinations up to K.
`--exhaustive_until` defaults to 2: pairs are enumerated exhaustively and larger
combinations are generated from unions of two retained K-1 combinations whose
union contains exactly K distinct branches. This heuristic is not an exhaustive
search of every possible high-order combination.

| `--high_order_pruning` | Which K−1 subsets can generate a K combination? |
| --- | --- |
| `all_cutoffs` (default) | Each retained subset must meet all specified cutoffs, including any ωC minimum. |
| `ocn_bound` | A subset meeting the literal `OCNany2spe` minimum can expand even if its ωC is low or undefined. Supports an optional `omegaCany2spe` cutoff for hits. |
| `auto` | Uses `ocn_bound` for these supported cutoff expressions and `all_cutoffs` otherwise. The choice depends only on the expression. |

The product of branch event probabilities at each site and destination can
only decrease as a branch is added. The ratio ωC can increase. This makes
the OCN minimum suitable for pruning and lets the final hit criterion use all
requested thresholds. The `high_order_pruning` column in `cb_stats.tsv`
reports the effective method for each heuristic expansion.

### Requiring site-level support for an OCN cutoff

Use `--min_ocn_site_pp 0.5` to sum only sites with probability at least
0.5 for the requested nonsynonymous event across the entire combination.
For `any2spe`, CSUBST sums over possible shared destination amino acids
within each site before applying the threshold. With the usual separate
branch posteriors the site value is the sum of products of branch event
probabilities. With `--pair_posterior joint` it is the fitted joint pair
probability. The existing `--min_sub_pp` acts earlier on individual branch
events and answers a different question.

For site probabilities of 0.2 at ten sites, raw OCN is 2 and the cutoff
sum is 0. Two sites at 0.8 contribute 1.6. A site exactly at 0.5 contributes
0.5. Each OCN category matched by `--cutoff_stat` has its own cutoff sum
in `cutoff_OCN<stat>` in the cb table. Parent selection, ranking at the
cap, observed-count pruning, and qualified-row summaries use this sum.
OCN, ECN, OCS, ECS and ωC retain their ordinary definitions. Exhaustive
tables still include rows below the hit thresholds. The default of 0 keeps
the usual unfiltered cutoff. Site-resolved evaluation takes additional work.

Beyond the exhaustive range (K ≥ 3), ordinary unsmoothed `ocn_bound` searches skip
expected counts for generated rows already below the observed minimum.
`num_generated` counts all generated rows and `ocn_bound_pruned` counts
the excluded rows. The cb table and medians describe the scored rows.
Observed-count regression and foreground enrichment use all generated rows.
Family-wide calibration, P values, clade permutation, site-filter
reports and epistasis retain the generated rows for scoring. If no generated
row meets the bound, the summary records the
terminal arity and the search ends before writing a cb table for it.

Without `--foreground`, all eligible subsets can expand. Placeholder foreground
labels do not restrict this search.
With a foreground file, each trait expands its own passing foreground, mixed,
and marginal combinations (`is_fg`, `is_mf`, or `is_mg` equals `Y`). A generated
combination must satisfy global phylogenetic independence and, beyond the
exhaustive range, the foreground independence constraints of the trait that
generated it. An unrelated trait cannot rescue a dependent combination. Rows
validly generated by another trait remain available, with dependency annotations
preserved separately for each trait.

`--max_combination` (default 10,000) caps the retained K-1 subsets after
cutoff and foreground selection. For each heuristic arity, `expansion_eligible`
counts these subsets before the cap, `expansion_cap_dropped` counts how many
the cap discards, and `num_generated` counts independent K combinations
constructed from the retained subsets. A single subset can participate in many
K combinations. When the cap applies, candidates are ranked in the order specified by
`--cutoff_stat`, descending. If a regex matches several columns, those columns
follow their table order within that expression's priority. Repeated matches
are used only once for ranking; every cutoff condition still applies. Exact
threshold equality passes; missing statistics do not pass.

With many branches or a long alignment, many subsets can pass a fixed OCN
minimum. At the default ranking (OCN first, ωC second), a high-OCN, low-ωC
subset can displace a subset that meets both thresholds. Either mode can then
miss hits recovered by the other. In the PEPC nine-stem urn search, a cap of 20
recovered 26 of 32 exhaustive K=3 hits with `all_cutoffs` and 22 with
`ocn_bound`. With room for every eligible pair the counts were 26 and 32.
[PEPC and candidate scaling measurements](../reports/branch_search_review/README.md#candidate-limits-and-alignment-length)

These selection rules apply to both `marginal` and `joint` substitution
posteriors. Their statistical values and eligible root-adjacent branches can
differ. See the [PEPC regression verification](../reports/search_candidate_fix_20260910/README.md)
and the [joint estimator guide](ENDPOINT_POSTERIORS.md).

## Measuring distance between branches

`search --branch_dist yes` reports `dist_bl`, the patristic distance
between the two parent nodes, in the branch-length units of the analysis
tree. This measures the separation of the two ancestral backgrounds before
the focal changes. Sisters have distance zero. For K > 2 the statistic is
the maximum over unordered pairs. `dist_parent_bl` is an alias for this value.
`sites` uses the same definition for `max_dist_bl` and its histogram.

The CSUBST paper uses “inter-branch distance” in Fig. 2b and Supplementary
Text 7 without specifying the endpoints there. Goldstein et al. (Fig. 1)
explicitly measured the ancestral-node path for this question. Zou and
Zhang (Fig. 2B and Methods) measured the path between the younger ends.
These choices include different amounts of evolution on the focal branches.
[Fukushima & Pollock 2023](https://doi.org/10.1038/s41559-022-01932-7) ·
[Supplementary Information, Text 7](https://media.springernature.com/full/springer-static/esm/art%3A10.1038%2Fs41559-022-01932-7/MediaObjects/41559_2022_1932_MOESM1_ESM.pdf) ·
[Goldstein et al. 2015](https://doi.org/10.1093/molbev/msv041) ·
[Zou & Zhang 2015](https://doi.org/10.1093/molbev/msv091)

The CSUBST version named in the paper (v0.20.17) computed the distance
between child nodes minus the length of the second branch. For independent
branches this includes the entire first branch. New tables retain this
ordered statistic in `dist_bl_legacy` (`max_dist_bl_legacy` in `sites`).
Use that column for comparisons to historical distance bins and cutoffs.
For example, with a parent-node path of 0.9 and focal branches of 0.1 and
0.4, `dist_bl` is 0.9 in either order. The historical values are 1.0
and 1.3 in the two orders.
[v0.20.17 distance calculation](https://github.com/kfuku52/csubst/blob/bbe7ef7ae3c7054d462c432877ec484f3efe3351/csubst/tree.py#L76-L92)

### Foreground clade permutations

At each arity reached by the observed search, `--fg_clade_permutation N`
draws clade sets for each trait, preserving the number of stems in each
clade-size bin. It enumerates independent K-branch combinations within
each draw. With `--fg_stem_only no`, the draw also includes descendants
of its sampled stems. Beyond the exhaustive range, `--fg_exclude_wg yes`
excludes combinations sharing a sampled foreground clade. The summary
compares the observed foreground median ωC with valid permuted medians at
that K. A joint null distribution for the highest qualifying K requires
reusing one clade draw across all arities and retaining draws with zero hits.
