**結論：ある。探索用途として妥当な近似に加えて、検定結果をそのまま採用すべきでない実装上の不整合がある。** 特に 3Di の codon-model 期待値、擬似カウント併用 P 値、エピスタシス自動推定、差分カテゴリの乱数生成を優先して扱うべきである。

## 1. 3Di の codon-model 期待値にアミノ酸 Q を適用している

**確認した経路：**

1. [parser_misc.py](../../csubst/parser_misc.py#L30) の初期化は `no` と `3di20` を同じ経路で扱い、各文字にアミノ酸の同義コドン集合を割り当てる。
2. [read_input](../../csubst/parser_misc.py#L369) はその集合から `instantaneous_nsy_rate_matrix` を生成する。
3. 後段の 3Di 準備は `state_nsy` を構造状態に置き換える。[該当箇所](../../csubst/parser_misc.py#L1070)
4. [期待値 reducer](../../csubst/omega.py#L2452) は、この構造状態に先の Q とコドン解析のサイト率を適用する。Q の代入箇所を全ソース検索したが、ここまでに 3Di 用 Q に更新する経路は見つからない。

3Di がアミノ酸と同じ 20 文字を使っていても文字の意味は異なる。3Di の `A` を alanine の遷移率で進化させる根拠にはならない。direct モードで IQ-TREE に GTR を当てはめても、その GTR を downstream ECN に使っているわけではない。

再現スクリプトでは 2 状態に縮約した初期化例で、`3di20` の Q が渡したコドン Q と同じになることを確認。実際の 20 状態 CLI 全体を再実行した検証ではなく、上記データフローの補助実験である。

**影響：** この組合せの ECN / dNC / omegaC を構造収斂のモデル較正済み統計量として使用すべきでない。scan には 3Di の q_weighted を state_aware に変更する処理があるため、この指摘を scan の Q にそのまま適用してはいけない。

**対応：** 3Di の Q、サイト率、枝長単位を一貫したものとして downstream に渡し、構造状態のラベルを一斉に置換しても統計量が変わらないことを確認する。それまでこの期待値方式の組合せを無効化するのが妥当。urn に変更するだけでは ID 9 の較正問題は解決しない。

## 2. 擬似カウント併用時、観測と帰無乱数に同じ変換を適用していない

[get_omega](../../csubst/omega.py#L3341) は擬似カウント補正済み値を通常の `omegaC*` に書く。一方、[add_omega_empirical_pvalues](../../csubst/omega.py#L3930) が呼ぶ [帰無 ω の計算](../../csubst/omega_statistics.py#L124) は未補正の乱数カウントと期待カウントの比を使う。

最小再現では OCN=1、ECN=10、OCS=10、ECS=10、対称 alpha=1 とし、**全 1,000 回の帰無カウントを観測カウントと完全に同じ**に固定した。観測 ω は 0.181818、帰無 ω は 0.1 となり、P=1/1001=0.000999 が出る。同じ統計量なら全試行が同値で P=1 になるべきである。

これは実データでの FPR 測定ではなく、乱数生成部を差し替えた比較処理の整合性検査だが、問題を帰無モデルの選択と切り離して示せる。

**対応：** 観測と乱数に同じ smoothing を適用する。alpha を固定条件とするか、推定手順ごと再実行するかも帰無仮説と合わせて定義する。修正までは smoothing と empirical omega P 値を併用しない。

## 3. エピスタシス自動推定の CV は、held-out データから作った特徴を使用する

[branch_context](../../csubst/omega.py#L222) は各枝の観測置換カウントで構造特徴を重み付けした平均である。[CV](../../csubst/omega.py#L350) は site prior を訓練枝から作り直すが、評価枝の `branch_context[test_rows]` は評価枝自身の観測から作ったまま使用する。

つまり、答えに含まれる「その枝の置換が構造特徴のどこに集中したか」を予測側に渡している。枝を分割しただけでは、この混入は除けない。

構造に依存しない一様な 20 サイトから各枝 1 イベント、500 枝を生成した最小実験でも、auto は beta=3 を選んだ。この単一 seed の実験は偽陽性率を示さないが、「CV で beta が選ばれたことがエピスタシスの証拠」という解釈は成立しない。

さらに計算自体は `base_probability × exp(beta × branch_context × site_feature)` を正規化する構造特徴に基づく重み付けで、残基状態間の相互作用や、遺伝背景による変異効果の変化を直接モデル化していない。固定 beta にも「生物学的エピスタシスを補正できた」という保証はない。

[既存の評価ツール](../../tools/evaluate_epistasis_simulation.py#L186) は epi_signal 条件で既知の収斂サイトに高い構造特徴を与える。これは有用な人工的ストレステストだが、独立に生成したエピスタティック進化過程からの検証ではない。

**対応：** context を独立データまたは評価対象を含まない過去の情報から作る、あるいは context 推定を含む生成モデルとして尤度化する。独立した epistatic simulator、非エピスタシス null、系統を考慮した分割で再検証する。現状は構造特徴による探索的重み付けと呼ぶのが正確。

## 4. dif 系カテゴリの帰無カウントの入れ子関係が壊れる

[各 base mode の乱数生成](../../csubst/omega.py#L3990) は mode ごとに独立の乱数ストリームを使う。[差分処理](../../csubst/omega.py#L3443) は例えば `any2dif = any2any - any2spe` を取る。

同じ置換履歴では必ず `any2spe <= any2any` だが、別々に乱数化すれば保証されない。負値を NaN にする実装は数値異常を隠さない点ではよい。しかし [P 値の分母](../../csubst/omega_statistics.py#L164) から NaN 試行が外れるため、正しい入れ子の同時分布には戻らない。

極端な例として全イベントが specific で双方の平均が 1 の場合、本来の差分は常に 0。一方、独立 Poisson(1) を現在の差分関数に渡すと、20 万回中 34.517% が NaN、34.5675% が正値となった。これは同時分布の破綻の例であり、全 null mode の影響率を測定したものではない。

**対応：** 一つの原子的な置換履歴から全 base / dif カテゴリを同時に集計する。単なる負値クリッピングや NaN 除去では修正にならない。修正まで dif 系 P / q 値の確証的利用を避ける。

## 5. scan の解析的 P 値は小標本でも過小になり得る

[Poisson LRT](../../csubst/substitution_scan.py#L1488) は、前景 rate が高い場合 `0.5 * chi2.sf(LRT, 1)` を返す。これは漸近近似である。既定の最小支持数が 2 なので、漸近性に期待できない候補も通常の対象になる。

等しい exposure、前景 2 イベント、背景 0 イベントでは、この関数の P=0.04795。一方、真の独立 Poisson 整数カウントを仮定して総数に条件付けた exact test は P=0.25。この比較だけでも「2 イベントで名目 5% を超える判断」の危険を示す。exact conditional test は posterior の小数カウントへそのまま適用できる解決策ではない。

さらに候補を前景で発見し、同じデータで前景 enrichment を検定している。[候補生成](../../csubst/substitution_scan.py#L1227)。BH 補正は候補選択によるバイアスを自動では補正しない。既定 posterior_sum は背景の弱いイベントも rate 計算に含める点で改善だが、post-selection 問題は残る。

**対応：** 解析的 P / q は順位付けと明記。full_scan の結果を併記し、ID 6 の条件を確認。確証的検定には fitted null から配列を生成し、ASR・候補抽出を含めて再実行する検証が必要。

## 6. full_scan は有益だが、無条件に FWER を保証するものではない

現在の [full_scan](../../csubst/substitution_scan.py#L2387) は候補抽出をやり直し、各試行の最小解析的 P と比較する。解析的 P のみ、または候補を固定する candidate_fixed より、候補探索を考慮する設計として優れている。

ただし次の条件は別途必要である。

- サイズ bin が同じ clade 間で、帰無のもとで対象ラベルを交換できること。サイズだけでは枝長、深さ、組成、欠損、ASR 精度、背景制約の違いは揃わない。
- [抽出処理](../../csubst/foreground.py#L509) は順次 clade を選んで重複を禁止するため、有効な clade 集合が一様に抽出されるとは限らない。非一様であることだけで無効とは断定できないが、観測対象と同じ生成法・適切な重み付けの根拠が必要。
- 既定では元の foreground clade を除外し、[失敗時には含めて再試行](../../csubst/substitution_scan.py#L2269) する。観測 configuration の +1 を足すことだけでこの設計の交換可能性は成立しない。
- [失敗した試行](../../csubst/substitution_scan.py#L2511) を除いて成功回数を分母にする。失敗が configuration に依存するなら、成功条件付きの帰無になる。
- 強い FWER 保証には、完全帰無での較正だけでなく、一部に真のシグナルがある場合の条件も必要。複数遺伝子・複数実行にまたがる探索は一回の full_scan の補正対象外。

ランダム置換の妥当性には帰無の不変性やサンプリング設計の条件が必要という点は [Hemerik & Goeman (2018)](https://link.springer.com/article/10.1007/s11749-017-0571-1) に対応する。ここでは現行 clade sampler の型 I 誤差保証を証明も否定もしていない。

**対応：** null 下の FPR/FWER を、系統形状・前景サイズ・欠損・率不均一・帰無/真陽性混在を変えて測る。成功率、重複を除いた configuration 数、抽出確率、foreground inclusion 条件を記録する。1,000 試行の最小 P は約 0.001 であり、全ゲノム水準の精度とは限らない。

## 7. Q-weighted exposure は完全な置換機会ではない

[exposure](../../csubst/substitution_scan.py#L1550) は親状態確率に瞬間 Q を掛け、枝長でスケールする。観測側は親子の端点状態の違いである。これは短い枝・少ない多重置換では理解可能な近似だが、枝の途中の状態滞在時間を積分していない。

Q の直接遷移が 0 でも中間状態を経由すれば `expm(Qt)` の端点遷移確率は正になる。3 状態例で 0→2 の exposure=0、端点遷移確率=0.15769 を確認。候補にイベントがあるのに機会がゼロになる、あるいは親が既に derived state なら枝内での復帰・再到達を機会に含められない状況がある。ECM 型のように多塩基瞬間遷移を許す Q と、単塩基型 Q では発生条件が異なる。

**対応：** endpoint probability と比較するか、CTMC bridge / stochastic mapping の期待遷移回数・滞在時間に分子分母を揃える。現状は枝長を変えた感度解析と exposure=0 の候補の監査が必要。

## 8. event_pp は一般には置換の joint posterior ではない

[置換テンソル](../../csubst/substitution.py#L334) は `P(parent=a|D) * P(child=d|D)` を使う。一般には `P(parent=a, child=d|D)` と等しくない。例えば枝長 0 で両端が完全に相関し、A/B の周辺分布が各 0.5 なら、真の状態変化確率は 0 だが積による off-diagonal mass は 0.5。

この例は数学的な極限の説明で、実際の枝長 0 の CLI 入力を用いた実験ではない。コードにおける積の式とその意味の違いを示す。

枝の端点 joint probability を求める方法は [SubRecon](https://academic.oup.com/bioinformatics/article/34/13/2297/4913808) でも明示的に扱われている。joint endpoint であっても複数ヒットの回数そのものにはならない点にも注意。

これは既存 ωC のシミュレーション上の有用性を否定しない。観測と期待の比、S による補正で相殺される部分があり得る。ただし `event_pp=0.8` を「置換した確率が厳密に 80%」と説明したり、イベントの独立性を仮定した検定へそのまま投入したりする根拠は弱い。曖昧な ASR、祖先を共有する枝、長い枝で重点検証が必要。

## 9. 3Di 予測は構造収斂の測定・較正とは別問題

[translate](../../csubst/structural_alphabet.py#L163) はアミノ酸 posterior を argmax 配列にし、予測した 3Di を one-hot 化する。アミノ酸 ASR の不確実性も予測器の不確実性も event_pp に残らない。direct は祖先 3Di posterior を持てるが、予測した末端文字を観測値として条件付けるため、予測誤差を積分してはいない。

3Di は配列文脈・立体環境に依存するので、ある列の構造状態変化がその列のコドン置換を意味するとは限らない。コドン同義収斂を分母にした ωC が通常 AA と同じ帰無解釈を保つことは、独立に確かめる必要がある。GTR の当てはめだけで状態間・サイト間の相関や予測器の系統的誤りは消えない。

[ProstT5 原著](https://academic.oup.com/nargab/article/6/4/lqae150/7901286) は相同性検索などで有用性を示す一方、3Di の per-residue 正解率として 41–65% の値も報告している。この値を ESM3Di や本データセットの正解率に転用してはいけないが、検索性能と文字単位の進化イベント精度は別物であることを示している。リポジトリの速度・CPU/CUDA 一致検証も生物学的精度の検証を代替しない。

**対応：** 実構造由来 3Di、既知祖先、予測誤差を入れた null、対象タンパク質群でのモデル外評価を行う。それまでは「予測構造状態の反復変化候補」として提示する。

## 10. longtail calibration は真のシグナルも抑え得る

[補正](../../csubst/omega_statistics.py#L40) は dSC の順位を dNC の経験分布に写し、元の dSC と比べて大きい方を使う。したがって有限な非負値では ω を上げず、下げる方向の補正である。偽陽性を作る補正だと一律に批判するのは正しくない。

しかし補正量は同時に含める枝組合せに依存する。小標本、前景だけの解析、シグナルが多数ある集合では、dNC 分布が帰無を代表しない。1 行だけで dNC=10、dSC=1 なら ω=10 が 1 になることを確認した。これは関数の境界例であり、既定の通常の全枝解析が必ず 1 行になるという主張ではない。

現在は [適用 arity の制限](../../csubst/main_analyze.py#L231)、未補正列の保存、較正後 P 値の再計算がある。これらは評価すべき対策である。

**対応：** `_nocalib` を併記し、枝集合の変更に対する安定性と power を確認。独立な帰無からの補正と比較する。較正後 ω の閾値を元のモデルの理論的閾値と同一視しない。

## 11. 既定の invariant-site 除外は単なる高速化ではない

[CLI](../../csubst/cli.py#L740) の既定は `tip_invariant`。[処理](../../csubst/parser_misc.py#L972) は末端コドン不変サイトを観測・期待の両計算から除くが、末端不変は祖先不変・帰無期待値ゼロを意味しない。欠損が多く 1 末端だけ観測できた列も除かれる。

特に 3Di では末端コドンが同じ列でも周囲配列の違いから構造状態が異なり得るため、このフィルタが構造シグナルを落とす可能性がある。`zero_sub_mass` も「観測 mass が 0」であり「モデル期待値も 0」の保証ではない。

フィルタ済みサイト集合を推定対象として明示し、同じ選別を含めて null を較正するなら合理的な設計になり得る。ただし全サイト解析と数学的に同値な最適化ではない。今回、実データでどの程度 ω が変わるかは測っていない。

**対応：** `no` との比較、除外サイトの期待 ECN/ECS の検査、3Di では構造状態も考慮した選別が必要。

## 12. urn・ASRV・擬似カウント・recoding の「名称」と科学的保証を分ける

- **urn / ASRV**：観測カウントからサイト重みを推定する経験的帰無。`each` の疎なカテゴリ、alpha による平滑化、foreground 自身のシグナル混入に結果が依存し得る。固定 alpha が誤りという意味ではなく、その値で FPR/power が較正されているかが課題。
- **poisson_full**：[各枝・サイトの観測 mass](../../csubst/omega.py#L3755) を使って平均を作るため、観測された集中を帰無が吸収し得る。「full」は完全な系統生成モデルを意味しない。
- **nbinom auto**：[観測と期待の分散から alpha を推定](../../csubst/omega.py#L3588) するため、真のシグナルと過分散を分離できるか、推定不確実性を無視してよいかの確認が必要。
- **Wallenius**：[小さい問題では厳密列挙、一定規模を超えると近似式](../../csubst/omega.py#L1477) に切り替わる。これは明確な実装仕様であり、全サイズで厳密な期待値と説明してはいけない。今回、近似誤差の代表的な大きさは測っていない。
- **pseudocount auto**：[Gamma–Poisson 周辺尤度](../../csubst/pseudocount.py#L191) を用いるが、実際の値は小数の posterior mass、枝を共有する組合せは相関する。理想的な独立整数 Poisson 標本の EB と同じ保証にはならない。正則化としては有用でも ID 2 の併用バグは別途直す必要がある。
- **固定 AA recoding**：化学的グループへの集約自体は合理的。ただし同じグループへの収斂は同じアミノ酸への収斂と異なる仮説。**自動 recoding** はデータ適応的で、複数方式を試して最良結果を選ぶならその探索も補正対象となる。
- **集約 Q**：[codon-to-group](../../csubst/parser_misc.py#L513) はコドン間 Q をブロックで単純合計する。厳密な周辺 CTMC の成立には lumpability 等の追加条件が必要で、一般の GY/MG/ECM の AA 集約で自動成立はしない。これは従来手法の経験的検証と併せて評価すべきモデル近似であり、直ちに全 ωC を無効とする指摘ではない。

## 13. 探索した候補だけの BH は探索全体の FDR ではない

[高次探索](../../csubst/main_analyze.py#L148) は下位 arity の cutoff を通過した組合せから候補を作り、max_combination で絞る。一方 [BH](../../csubst/omega.py#L4070) は現在のテーブル・stat ごとの P 値に適用される。探索に用いた同じシグナル、複数 stat、複数 arity、複数遺伝子、recoding の選択まで含めた family の補正ではない。

加えて empirical P の [段階的 refinement](../../csubst/omega.py#L4040) は超過回数を見て追加試行を選ぶ。固定試行数の `(r+1)/(B+1)` の理論を任意の停止規則へそのまま適用できるとは限らない。今回その誤差率は未測定であり、バグと断定せず要検証事項とする。

**対応：** family を事前定義し、候補探索全体の再実行、独立確認データ、または選択を扱う推論を利用する。Monte Carlo は固定予算との比較や逐次検定としての保証を確認する。

## 基本手法をどこまで信頼できるか

通常 AA の codon-model ωC には [Fukushima & Pollock (2023)](https://www.nature.com/articles/s41559-022-01932-7) の理論的動機とシミュレーション・実例の裏付けがある。上記の拡張の問題から、その基本手法まで一律に科学的根拠なしとするのは不適切。ただし原著の検証が、後から追加された 3Di、urn P 値、epistasis、scan に自動的に引き継がれるわけでもない。

scan は前景の反復置換を一覧化し、支持枝・状態・exposure を監査する用途には有用。rate enrichment が認められても、その原因を自然選択、表現型への因果効果、機能的適応と同定するには別の証拠が必要である。

## 優先順位と必要な検証

1. ID 1–4 を先に修正または該当組合せを無効化。統計量の同一性、ラベル置換不変性、カテゴリの入れ子、評価データ非混入を回帰テスト化。
2. scan の解析的 P / empirical P / maxT の解釈を分離。帰無で配列生成→ASR→候補探索→最終選択まで実行して FPR/FWER を測る。
3. 短枝/長枝、平衡組成変化、サイト制約、系統誤差、欠損、前景数、背景の不均一を変える。名目 0.05 だけでなく小さい alpha と Monte Carlo 信頼区間も報告する。
4. 3Di は実構造由来データとの比較と予測誤差モデルを独立に検証する。
5. 長尾補正、サイト除外、ASRV alpha、recoding、枝集合について効果量と検出候補の感度解析を行う。
