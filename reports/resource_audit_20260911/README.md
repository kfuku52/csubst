# 2026-09-11 修正・RAM/実行時間・worktree監査

9月8日の `286ac2b`（1.14.11）と、9月11日の `2ae3a0a`（1.15.2）に今回の `+I` 修正を加えた版を比較した。
**条件によって大幅な増加がある。** 新既定のjoint検索、特に `spe2spe` を含む全統計、最大arityを増やす検索、endpoint scanは個別に扱う必要がある。
推定方式・既定のサイト除外・校正の変更があるため、旧版と新版の既定実行は同じ数値を計算する比較ではない。

## 今回の修正

- IQ-TREEが純粋な `+I` の不変サイト割合を0と推定してカテゴリ表を省略した場合を、正しく単一の単位速度カテゴリとして読み込む。正の割合や情報不足、Invar+Gamma等を一律に単位速度へ置換しない。
- 追跡済み検証ログ内の個人ホームパスを匿名化し、必須のrepository hygiene検査を通す。
- 境界値の回帰テスト、実IQ-TREEによる再現、以前のレビュー記録を保存した。元の指摘と検証範囲は [レビュー報告](../review_20260911_2ae3a0a/README.md)。

## 測定方法と範囲

- 同じmacOS 26.6.2、64 GiBホスト、x86_64 Python 3.10.14。NumPy 1.26.4、SciPy 1.15.2、pandas 2.2.3、Cython 3.0.11。各版の6個のnative拡張を同じ環境でビルドした。旧版と新版の拡張を混用していない。
- 1プロセスずつ逐次実行。CSUBST・BLAS各1スレッド、seed=8、小数12桁。各条件1回warmup後、3回を計測し、before/afterの順序を交互にした。時間は親プロセスで測ったCLI全体のwall time、RAMはmacOS `/usr/bin/time -l` の子プロセス最大RSS。MiB=2^20 bytes。
- 同梱PGK（33種×417コドン）、PEPC（71種×971コドン）の同じ既存fitted filesを明示指定。IQ-TREE再推定やダウンロード時間は含まない。
- PEPC×4は同じアラインメント・state・rateのサイト軸を4回連結した3,884コドンの形状負荷試験。系統樹・モデル・パラメータは固定で、新しく推定した生物学的データではない。
- searchは特記なしではK=2。scanは図を無効化し、原則として校正なし。`pgk_scan_calibration20`だけfull_scan校正を20反復する。sitesは枝0,2、図を無効化。
- 本測定中には別のテスト・ビルド・ベンチマークを並走させていない。ただし専用の無負荷ホストではなく、各実行中のホストCPU負荷をJSONに記録した。単発の外れ値や小さな差から高速化を主張しない。

## 数値の比較について

旧版には再root時に内部節点名が移動する問題があり、現行版で修正されている。このため `marginal`、全サイト、校正なしにそろえた最初の比較でも、出力行数がPGK 1,682→1,620、PEPC 8,446→8,308と異なる。
変更節点に関係する枝を除いた共通行では主要18列が `rtol=1e-8, atol=1e-9` で一致するが、これを全体の数値同等性とは扱わない。

そこで、旧版にroot移動の修正だけを移植した追加対照を用意した。
[prepare_control.py](prepare_control.py) と [root-backport.patch](root-backport.patch) で変更を再現できる。
差分だけを適用する場合は旧版コピー内で `git apply --unidiff-zero root-backport.patch` を使う。
元の旧版を上書きせず、別ディレクトリにコピーして実行した。対照のソースhashも記録した。

この対照でPGK、PEPC、PEPC×4、PEPC全統計のcodon_model検索は、枝組合せと比較した全数値列が一致した（最大絶対差0）。一方、urnでは期待値と派生するdN/dS・omegaに差が残る。直近にWalleniusの2回抽出を厳密計算へ変更し、重みの正規化も修正されているため、urnの時間差を数値同等な処理の高速化・低速化として扱わない。PEPC urnの観測列は一致し、ECN/ECSの最大絶対差はそれぞれ0.000484/0.002114、omegaの最大絶対差は30.50だった。

## 増加が出る計算経路

全統計での大きな増加は、既定jointによる端点確率の再推定と、full-eventおよび `spe2spe` 投影行列の処理に対応する。
PEPCの実行ログでは入力・確率計算段階が旧版約1秒、新版約21秒。新版のN側 `spe2spe` 観測投影は約2,414万非ゼロ要素、期待投影は約4,307万非ゼロ要素を保持した。
通常のK=2検索で使える小さなpairwise集計経路を、この条件では使えない。単にスレッド数が変わった比較ではない。

根拠となる [旧全統計ログ](evidence/pepc_full-before-1.log) と [新全統計ログ](evidence/pepc_full-after-1.log) も保存した。

scanの旧既定はmarginal観測と `q_weighted`/`n_rescaled`、現既定はjoint観測と `endpoint`/`raw` である。
この追加計算を伴う既定比較と、旧設定へそろえた比較を分けている。`--substitution_posterior marginal` は科学的な推定方式を変更する指定であり、同じ結果を保つ高速化策とはいえない。

## 再現

[benchmark.py](benchmark.py) の `--baseline-root` と `--candidate-root` に同じ環境でnative拡張をビルドした各版を指定する。
`--cases` で測定条件を選択し、`--workdir` にCLI出力とログ、`--result` にJSONを保存する。
各JSONには全実行コマンド、入力・ソースhash、環境、warmupを含む個別時間・RSS、3反復の中央値・範囲、出力比較を記録した。
結果の比較列はJSONの `comparisons` に列挙される。指定列の許容誤差一致であり、異なる版の全ファイルがbyte一致するという主張ではない。
