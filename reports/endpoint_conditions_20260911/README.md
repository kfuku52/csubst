# Joint endpoint: 条件別ボトルネックと高速化

PGK/PEPC、出力統計・サイト別出力・再分類・arity・処理ブロックを変えた9条件を調査し、3点を改善した。最終ソースで72試行（各条件・各版のウォームアップ1回＋測定3回）を実施。176表の数値比較、枝ID、閾値判定がすべて一致した。

## 最終版の時間

秒、測定3回の中央値（最小–最大）。通常はCPU 1 / BLAS 1 / block 64 / arity 2。CPU 4・block 256を同時に変えた行から、CPUとブロックサイズそれぞれの効果は分離できない。

計測はCLI本体の開始から終了までで、入力読み込み・推論・集計・TSV出力・検証用pickle保存を含む。Python起動と共通モジュールの事前読み込みは除外。起動を含む時間も [matrix.json](matrix.json) に記録している。IQ-TREEの再推定は行っていない。

共有マシンで前後を交互に実行し、Pythonのハッシュシードを0、乱数シードを8、BLASを1に固定した。ホスト全体の稼働は約2.7–7.7 CPU相当で、外部負荷を完全には排除できていない。表の割合は観測された中央値の短縮幅であり、他環境で同じ割合を保証するものではない。特に数%の差や測定範囲が重なる条件は、明確な速度差とは解釈しない。PGKのサイト別・spe2spe条件にも遅い試行があったため、範囲を併記した。

## ボトルネックと採用した変更

1. **全イベントが必要な条件のコドン中間配列。** S/BS/CS、spe2spe、Dayhoff6の追加AAストリームでは、61×61の中間配列からS/N/AAへ変換していた。観測・期待値とも必要なイベント軸へ直接加算するよう変更した。後続が必要とする完全な疎イベント表は維持し、確率やイベントを削除していない。
2. **別BLASランタイムの初回実行コスト。** この環境のNumPyはOpenBLAS、SciPyはMKLにリンクされている。幅の広いGram行列だけSciPyのdsyrkへ切り替える処理を、NumPyの行列積へ統一した。実データから取り出した65×166800行列では、SciPy側の初回呼び出しは約1.38秒、以後は約0.05秒だった。NumPyは初回から約0.05秒で数値比較を通過した。[gram_diagnostic.log](gram_diagnostic.log) を参照。この初期化差は実行環境に依存する。
3. **小ブロックで繰り返す期待値の遷移行列集約。** 予測側の右尤度が1であることを利用して、遷移行列とNグループの積を先に計算し、各サイトブロックでは小さい行列を掛ける。配列ペイロード32 MiB（参照して保持する遷移行列も計上）・1024項目を上限とするLRUキャッシュを使う。Pythonオブジェクトの管理領域は別途必要。確率の切り捨ては行わない。block 8の診断では期待値変換の累積時間が約1.75→1.22秒だった。

診断値はプロファイル実行の値で、上表の非プロファイル測定とは別。[profiles.json](profiles.json) に呼び出し回数と主要な関数の時間を保存した。

## 残るボトルネックと試行

小ブロックではサイト・枝・速度カテゴリを回るPython処理と、ネイティブ関数への呼び出し回数がまだ支配的。サイト別出力では疎行列の投影・ソート・組合せ積、高arityでは疎投影の組合せ集計も残る。全条件が同程度に速くなったわけではない。

途中でS/N/AAを一括配列に詰める案を試したが、非連続な出力配列が後続処理に不利になり、PEPCで回帰したため取り下げた。その後、小ブロックのばらつきと遅い中央値を追加測定し、期待値集約キャッシュを追加して最終版を再測定した。途中の要約は [experiments.json](experiments.json)。最終結果として採用しているのは上表とmatrix.jsonだけである。

## 正しさと検証

176表中104表は完全一致、残る72表も浮動小数点の集計順序による差の範囲で一致した。件数の絶対・相対許容誤差は1e-10、比は検証済みの分子・分母の差を伝播した範囲内か検査。NaN/±Infの位置、枝ID、置換文字列、cutoff判定も比較した。実行時間を含む統計表は対象外。全比較の詳細はmatrix.jsonの各run.tablesに記録している。

arity 6で検出される組は `[1, 26, 33, 35, 40, 102]` の1組で変更なし。全体テスト2125 passed / 5 skipped、ネイティブ専用16 passed（全体と重複）、lint・文書検査・型検査も通過した。[checks.log](checks.log) を参照。新テストは、全イベントのPython参照実装との比較、再分類・混合速度・欠損・構造状態、幅広行列の正確なスカラー和との比較、キャッシュの同値性・無効化・追い出した遷移行列の解放を含む。実測の3Di性能や未収録データの性能はこの9条件からは判断しない。

## 再現

Apple M2 Max、64 GiB、12論理CPU、macOS x86_64実行、Python 3.10.14 / NumPy 1.26.4 / SciPy 1.15.2。変更前はこの依頼開始時の実装（前の高速化を含む）。コミット `72c3c45` のソースへ [baseline.patch](baseline.patch) を適用すると比較対象の3実装ファイルを復元できる。両ソースのネイティブ拡張を同じ互換環境でビルドする。最終測定後に、記録されたソース・拡張のハッシュが現在の作業ツリーと一致することも確認した。

```bash
python .github/scripts/benchmark_endpoint_conditions.py \
  --baseline-root /tmp/csubst-conditions-before-20260911 \
  --cases pepc_block8 pepc_branch pepc_arity6 pgk_pair pgk_sites \
          pgk_full pgk_recode pepc_pair pepc_block256 \
  --workdir /tmp/csubst-condition-cached-matrix \
  --result reports/endpoint_conditions_20260911/matrix.json --repeats 3
```

`--profile`を加えると、反復測定の代わりに各条件の変更前プロファイルを1回採取する。ワーカーのログと丸め前表はworkdirに保存される。全コマンドとハッシュはmatrix.jsonに含まれる。
