# Higher-order branch search

`csubst search --max_arity K` examines independent branch combinations up to K.
`--exhaustive_until` defaults to 2: pairs are enumerated exhaustively and larger
combinations are generated from unions of two retained K-1 combinations whose
union contains exactly K distinct branches. This heuristic is not an exhaustive
search of every possible high-order combination.

Without `--foreground`, all combinations that pass `--cutoff_stat` are eligible
for expansion. Placeholder foreground labels do not restrict this search.
With a foreground file, each trait expands its own passing foreground, mixed,
and marginal combinations (`is_fg`, `is_mf`, or `is_mg` equals `Y`). A generated
combination must satisfy global phylogenetic independence and, beyond the
exhaustive range, the foreground independence constraints of the trait that
generated it. An unrelated trait cannot rescue a dependent combination. Rows
validly generated by another trait remain available, with dependency annotations
preserved separately for each trait.

`--max_combination` caps the retained K-1 candidates, after the cutoff and
foreground eligibility filters. It does **not** cap the number of generated K
rows. When the cap applies, candidates are ranked in the order specified by
`--cutoff_stat`, descending. If a regex matches several columns, those columns
follow their table order within that expression's priority. Repeated matches
are used only once for ranking; every cutoff condition still applies. Exact
threshold equality passes; missing statistics do not pass.

These selection rules apply to both `marginal` and `joint` substitution
posteriors. Their statistical values and eligible root-adjacent branches can
differ. See the [PEPC regression verification](../reports/search_candidate_fix_20260910/README.md)
and the [joint estimator guide](ENDPOINT_POSTERIORS.md).
